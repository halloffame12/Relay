Two frustrations. One app.

Relay began with a lost page and a needlessly complicated transfer. It is an attempt to make both experiences boring in the best way.

An independent Android project, built in the open. No company behind it, no growth metrics in the copy, and no pretend testimonials.

The story

Read offline.
Continue where you stopped.
Share with a scan.

GitHub ↗

Relay started with two frustrations: losing your place while reading, and dealing with unnecessary steps when sharing files.

The first is small but constant. You close a PDF to answer something, come back, and the page is gone. The library knows the file exists, but not where you were in it. The second is louder. You want to send one document to the phone in front of you, and suddenly you are reading out an IP address, hunting for a port, or typing a six-digit code that expires while you find it.

The idea was to build one application that makes both experiences simpler. A library that keeps your position. A transfer that starts with a scan and asks the receiver before it writes anything.

Read offline. Continue where you stopped. Share with a scan.

That sentence set the constraints. The library had to work without a connection, so reading could not depend on a server. Sharing had to work without an account, so the handshake could not rely on a cloud identity. And the receiver had to stay in control, so the file list is shown and approved before the first byte is written.

The rest is engineering discipline. Stream files in bounded chunks instead of loading them into memory. Hash the bytes and compare them. Refuse to overwrite a document that already exists. Clean up after a cancelled transfer. Say which network path was used, rather than implying every network behaves the same.

Relay is still evolving. The published build handles same-network transfers; the cross-network path is written but needs a signaling endpoint. Features are added only when they work end to end, and the website is meant to describe the app that exists, not the one that might.

Principles

Rules the product is held to.

01

Local by default

The library, reading position and bookmarks live on the device. Reading is not a network feature.

02

Consent before bytes

The receiver sees the manifest and approves it. No file is written automatically, and nothing is auto-accepted.

03

Proof over promises

SHA-256 and byte counts are checked before import. The code is public, so the claim can be audited.

04

Honest limits

When a capability needs configuration or a network that permits it, the interface says so instead of pretending.

What Relay is not

A small tool, on purpose.

Not a cloud drive. Not a social reading network. Not a subscription. The scope is deliberately narrow, because the two core experiences are the point.

—No document uploads to cloud storage.
—No accounts, profiles or reading social graph.
—No ads, trackers or behavioral analytics.
—No claim that every network supports a direct connection.

Found something that does not match these statements? Open an issue.
