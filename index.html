02 / Sharing with a scan

The easiest way to explain file sharing: scan this.

Select a document. Show a QR code. Let the other device scan it. Review and approve. That's it.

The sender chooses PDFs or EPUBs from the Relay library. A batch can hold up to 20 files or 200 MiB, and each file is capped at 100 MiB.

PDF · EPUB20 files / 200 MiB

Relay opens a short-lived session on the device and renders it as a single-use code. The code carries a session reference and an ephemeral token, not an account or a long-lived secret.

5-minute expirySingle useNo long-lived secret

The receiver scans the code inside Relay. It is validated as a Relay envelope and never opened as a web link or an arbitrary URL.

Camera only while scanningNever opened as a link

The receiver sees the sender name, file names, formats and sizes, then approves or declines. Nothing is written to storage before that approval.

Receiver consentNothing saved yet

Files stream in chunks with bounded memory. The receiver requires the declared byte count and SHA-256 to match before anything is imported. A duplicate is reported, never overwritten.

Bounded memorySHA-256No silent overwrite

03 / Across networks

Your devices don't have to share a Wi-Fi network.

Relay is designed to connect devices across different networks. It prefers direct device-to-device connections and uses relay infrastructure when a direct connection isn't available.

There is no address to type and no route to choose. Relay picks the path and labels the one it used.

→

Direct peer-to-peer

On the same network, the two devices connect to each other. Nothing sits in the middle.

→

Signaling for the introduction

A small WebSocket room exchanges session and connection metadata. It does not carry file bytes.

→

Relay only as a fallback

When a restrictive network blocks a direct path, TURN relays encrypted WebRTC packets.

The published 0.9.0 APK transfers between devices on the same network. Cross-network support is implemented, but that build needs a configured signaling endpoint; the app states which mode it is in. How the connection is chosen

Signaling / relay sees

  • Session and room identifiers
  • IP addresses and connection metadata
  • Transfer volume, if TURN is used

Never

  • Your document contents
  • Your library or reading history
  • An account or profile

04 / Built with care

A transfer should arrive exactly as it was sent.

The receiver holds the last word, and the bytes have to prove themselves before anything joins the library.

01Byte countThe declared size is checked against what actually arrived. A short or oversized file is rejected.Checked
02SHA-256Both sides hash the stream. The receiver requires a matching digest before import.Verified
03Duplicate detectionA document already in the library is reported as a duplicate, never silently replaced.No overwrite
04Explicit approvalThe receiver sees the file list and approves it. Nothing is written before that moment.Consent
05Interrupted transfersCancelling closes the connection and removes temporary data. No half-written entry is left behind.Clean

These are implementation checks, not marketing guarantees. You can read the protocol and verification code in the public repository.

05 / No accounts

Your documents don't need another cloud account.

Relay has no sign-up, no profile and no document sync service. The library is yours, on the device. Sharing happens between two Relay devices, not through a cloud library.

Signaling is a connection helper, not storage. It introduces two devices and then steps out of the file path. Relay never uploads your documents to cloud storage.

Read the privacy details →

What Relay has

  • A local document library
  • On-device reading progress and bookmarks
  • Camera access only while scanning
  • A direct path that needs no account

What it does not

  • Registration or sign-in
  • Cloud document storage
  • Ads or behavioral analytics
  • Automatic file acceptance

Local network transfers use Relay's own TCP path. WebRTC paths are DTLS-encrypted. Relay does not claim end-to-end encryption for the local TCP path.
