How it works

A transfer in six beats.

From picking a file to opening it on the other device, with approval and verification in between.

01

Offer to receive

On the receiving device, Relay opens a session and shows a single-use QR code. It never exposes other files on that device.

02

Scan

The sender scans the code. Relay validates it as Relay data, never as a URL, and connects automatically.

03

Choose

The sender picks a document from the Relay library and confirms. The receiver sees its name, format and size.

04

Approve

The receiver explicitly approves. Nothing is written before that moment.

05

Transfer and verify

Bytes stream with bounded memory. Both sides compute SHA-256. The receiver requires the declared size and hash to match.

06

Import

The verified file is imported into the receiver's library. A duplicate is reported, never overwriting the existing copy.

Connections

Direct first. Relayed when needed.

Relay tries a direct device-to-device connection first. When a direct path is unavailable, it can use a relay. You never choose between them and you never type an address.

When a relay is used, it carries encrypted packets, not file contents, and sees source and destination addresses plus transfer volume.

Cross-network transfer needs a deployed signaling service. When it is not configured, the app runs the local network path only and says so.

When things fail

No partial mess.

An interrupted transfer leaves no library entry and removes its temporary file. A mismatched checksum or size is rejected before import. Cancelling closes the connection and records an interrupted transfer rather than a success.
