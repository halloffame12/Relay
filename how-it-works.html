How it worksReading / Sharing

Two experiences. One app.

Reading that remembers you, and sharing that needs nothing more than a scan. Here is the whole flow, without the networking vocabulary.

Everything below reflects the 0.9.0 implementation. Where a capability depends on configuration, it says so.

01

Import a PDF or EPUB

Choose a file through the Android system picker. Relay copies it into app-managed storage, computes SHA-256 and rejects a duplicate instead of replacing an existing document.

02

Open it in Relay

The reader restores your last position and keeps bookmarks with the document. PDF pages and EPUB chapters are rendered locally.

03

Read offline

No account, no server and no connection is required. Reading progress lives in the on-device library.

04

Come back and continue

Close the app whenever you need to. The next time you open the document, it starts where you stopped.

01

Select a document

The sender picks one document or a batch from the Relay library. Up to 20 files or 200 MiB per batch, with a 100 MiB cap per file.

02

Show a QR code

Relay opens a short-lived session and renders a single-use code. It expires in minutes and contains no long-lived secret.

03

Scan from the other device

The receiver scans the code in Relay. The code is validated as Relay data and is never opened as a URL.

04

Review and approve

The receiver sees the sender name, file names, formats and sizes before approving. Nothing is written before that moment.

05

Transfer and verify

Files stream with bounded memory. SHA-256 and the declared byte count are checked before import; an interrupted transfer leaves no library entry.

Connection paths

Direct first. Relayed only when needed.

Relay tries the shortest path it can find. You do not choose a route, type an address, or open a port.

  1. Same network. The devices find each other on the local network and transfer directly. Nothing in the path stores the document.
  2. Different networks. A small signaling room exchanges session and connection metadata so the devices can attempt a direct WebRTC connection. It never receives file bytes.
  3. Restrictive network. If no direct path works, TURN relays encrypted WebRTC packets. The relay forwards traffic; it does not keep a copy.

Not every network permits a direct connection, and Relay does not pretend otherwise. The app labels the path it actually used.
