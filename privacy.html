PrivacyUpdated November 2026

Privacy, in plain terms.

Relay is local-first. There is no account, no document cloud, and no behavioral analytics. This page describes exactly what leaves the device, and when.

This policy covers the Android app and this static website. The source is public, so every statement can be checked against the implementation.

1. Your library stays on your device

Imported PDF and EPUB files, reading positions, bookmarks and library metadata are stored in Relay's private application storage on the device, backed by a local SQLite database (Drift). Relay operates no document storage service and does not synchronise your library to a server.

Removing a document deletes Relay's managed copy. If you imported the file from another location, that original is not touched.

2. No account, no profile

Relay has no registration, sign-in, email address or user profile. Nothing in the app requires an identity to read, import or share a document.

3. Camera

Camera access is requested only when you open the QR scanner, and only to read a Relay invitation code. Frames are processed on the device by the scanner library and are not recorded, stored or uploaded by Relay. Relay does not treat scanned text as a web link; it validates the relay envelope and rejects anything else.

You can deny or revoke camera permission in Android settings. The rest of the app, including reading and importing, continues to work.

4. Files and storage access

Imports use the Android system file picker (Storage Access Framework). Relay only reads the files you explicitly select, then copies them into its own app-managed directory.

5. Transfer metadata

Relay supports two connection paths. Which one is used depends on the build and the network:

  • Local network (TCP). The two devices connect directly using local addresses. File bytes do not pass through a Relay server. This path is not encrypted at the transport level, so avoid sensitive transfers on untrusted or public Wi-Fi.
  • WebRTC (direct or relayed). When a signaling endpoint is configured, a WebSocket service introduces the two devices and exchanges session and ICE metadata. WebRTC data channels are encrypted with DTLS. If a direct path fails, TURN relays encrypted packets; the relay can observe source and destination addresses and transfer volume, but not the decrypted document.

The signaling service may process room identifiers, session identifiers, IP addresses, connection metadata and timestamps. The reference server does not log request contents and does not store documents. A hosting provider may still keep infrastructure-level network logs under its own policy.

6. Analytics, ads and tracking

Relay contains no advertising SDKs, no behavioral analytics and no third-party trackers. No reading activity, file name, search term or transfer history is sent to Relay.

This website is a static site. It does not set analytics cookies. It stores only your light or dark theme preference in your browser's local storage. No account or contact form data is collected here.

7. Permissions summary

  • Camera: QR scanning, while the scanner is open.
  • Network: local transfers and, if configured, signaling and WebRTC.
  • Files: through the system picker; Relay writes only to its own storage.

8. Children

Relay is a general-purpose document tool and is not directed at children. It does not knowingly collect personal information from anyone, because it does not collect accounts or profiles.

9. Changes

If data handling changes, this page will be updated with the release that introduces the change. The implementation remains the authoritative description.

10. Contact

Questions or corrections can be raised through the public issue tracker at github.com/halloffame12/Relay/issues. Please do not include sensitive personal documents in a public issue.
